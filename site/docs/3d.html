Spin or tilt an object, and it clicks into the nearest face. A flick carries it on, then it lands with no bounce. It hands you the rotation for CSS 3D or three.js, and draws nothing.

Resting on: Front. Screen readers hear: nothing yet.

The cube reads the three variables. CSS applies them right to left: roll, then pitch, then yaw.

.cube { transform: rotateY(calc(var(--yaw) * 1deg)) rotateX(calc(var(--pitch) * 1deg)) rotateZ(calc(var(--roll) * 1deg)); }

Drag it any way, or tab to it and press the arrow keys. A drag to the right turns the front to the right, so the left side comes round. Free turns use quaternions, so it never locks up over the top and always takes the short way to a face.

A product turntable

Eight views of a box, every 45 degrees round its upright axis. On one axis it is a slider, so a screen reader hears the view's name as its value.

This side up

The arrow keys go one view, Page Up and Page Down a quarter turn, Home and End to the first and last. It goes round: past the last view comes the first, the short way.

With three.js

onInput gives a quaternion as [x, y, z, w] in three.js axes, with y up. Pass it straight on: model.quaternion.set(...q). There is a full example in Recipes.

The degrees are for CSS: yaw turns round the upright axis, positive to the right. pitch tilts, positive tilts the front up, so -90 shows the top. roll turns round the line of sight, clockwise like CSS rotate. On one axis the angle keeps counting past a full turn, so it never jumps.

Name it with aria-label, as you would any control. Mark the drawn faces aria-hidden="true", so a screen reader does not read all six at once. It sets touch-action: none on the element only, so the page still scrolls everywhere else.
