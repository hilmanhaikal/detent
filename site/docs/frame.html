Frame budget

Every detent module moves on one shared frame: one requestAnimationFrame however much moves. It stops in a hidden tab. When frames run long, as on a low-end phone, it eases off, and every motion still lands exactly where it should.

A busy page

Make the page busy and watch the spring. It draws fewer frames, keeps to the clock and lands on the same place.

Measuring.

What it does

  • One frame. Controls, page settles, animations and timelines all ask the same frame. Ten things moving cost one requestAnimationFrame, not ten.
  • Hidden tabs. Browsers stop frames in a hidden tab, so nothing is drawn there. animate() and timeline() stop their time too and go on from the same place. A control that was settling lands where it was going.
  • Stalled frames. If no frame comes for 100 ms while the page is shown (some phones, CI WebKit), a timer stands in, so motion still ends on time.
  • Slow phones. It keeps a running average of the time between frames. Past 28 ms a frame the budget is low, and motion is drawn every other frame, which halves the style writes. Below 20 ms it is back to every frame. Two lines, so it does not flip back and forth.
  • Never a wrong end. Every motion runs on real elapsed time and writes its end value when it lands. A skipped frame changes how smooth it looks, never where it ends. Your hand is never skipped: a drag follows the pointer events, not the frame.

Read it in your app

import { frame, frameBudget } from '@hlmnhkl/detent'

frameBudget.low // true when recent frames run long: show fewer effects
frameBudget.frameMs // the recent time between frames, in ms
frameBudget.force(true) // a "save power" setting in your app; null measures again

const cancel = frame((now) => draw(now)) // your own work, on the same shared frame
